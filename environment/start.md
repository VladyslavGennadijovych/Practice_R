# Запуск хмарного середовища Practice_R

Працюйте в наявному репозиторії `/workspace/Practice_R`. Кожне хмарне завдання вже ізольоване; створюйте Git worktree лише за прямим запитом користувача. Перед роботою прочитайте актуальні README та AGENTS.md, якщо вони є.

У кожній новій оболонці Bash:

```bash
cd /workspace/Practice_R
source scripts/activate-r.sh
Rscript --vanilla scripts/check-r.R
bash scripts/check-native.sh
```

Очікується 5/5 перевірок R і 3/3 перевірок розширень. Це перевірки середовища; тести прикладного коду запускайте окремо відповідно до інструкцій проєкту.

R 4.5.3, стандартні пакети, renv 1.3.1 і компілятори зберігаються у `/workspace/.practice-r-setup`. Активація налаштовує шляхи до R, компіляторів, бібліотеки пакетів і кешів. Фонові сервіси не потрібні. Для інтерактивної консолі використовуйте `R --no-save`, для власних скриптів — `Rscript шлях/до/скрипту.R`.

Якщо інструментів немає або потрібно повторити встановлення:

```bash
cd /workspace/Practice_R
bash scripts/setup-r.sh
```

Інсталятор використовує зафіксований список `environment/conda-linux-64.lock`, перевіряє контрольні суми й запускає всі вісім перевірок. Micromamba потребує стандартного реєстру `~/.conda`; якщо створення або запис заблоковано, використовуйте штатний запит дозволу на цей каталог. Не вимикайте TLS або перевірку контрольних сум.

Для додаткових пакетів із CRAN потрібен дозволений HTTPS-доступ до `cloud.r-project.org`. Мережеві вимоги наведено в README. Зміни політики застосовуються через налаштування середовища; збереження чернетки не підтверджує їх застосування. Після зміни перевірте доступ:

```bash
curl --fail --head https://cloud.r-project.org/src/contrib/PACKAGES.gz
```

Під час налаштування перевіряйте `git status` до й після роботи; зберігайте наявні зміни користувача. Не створюйте файли проєкту чи lockfile командою `renv::init()` лише для запуску середовища. Якщо з'явиться власний lockfile проєкту, дотримуйтеся документованої процедури відновлення залежностей. Публікація хмарного середовища та перевірка його відновлення в новому завданні — окремі дії.
